# Chain Hub

Chain Hub is a local-first AI workspace control plane. One hub folder
(`~/.chain-hub`) is the single source of truth, one CLI (`chain`) manages it,
one dashboard gives visual control, and every editor you use — Cursor, Claude
Code, Windsurf, Zed — reads a synced copy.

## Core philosophy

Local-first, editor-agnostic, minimal surface, grows deliberately.

## Two surfaces, one hub folder

**CLI** — the system engine: initialize hub storage, manage assets, validate
structure, connect editors, run the local hub server.

**Hub Dashboard** — the visual control plane: show system health, guide
setup, browse assets, inspect integrations, run high-confidence actions.

## Five asset kinds

- **Skills** — reusable capabilities your editor can invoke on demand.
- **Agents** — personas and behavior presets tuned for specific work.
- **Workflows** — multi-step processes captured once, run everywhere.
- **Rules** — guardrails and conventions your AI tools always follow.
- **Prompts** — one-shot reusable prompt text for a specific task; library-only, not synced to editors.

Assets live in the Library and sync out to your editors — see
[Editor Setup](/editor-setup) for exactly which editor gets which kind.

## Learnings: a separate thing from assets

**Learnings** isn't an asset kind — it's the hub's own capture-and-reflect
system, stored under `~/.chain-hub/memory/`. You capture events
(`chain capture --event success|failure|correction|note`) as you work, and
`chain reflect` turns the accumulated events for a skill into a written
reflection. A seeded rule (`chain-hub-learnings`) asks your connected
editors to call `chain capture` automatically; see the Learnings dashboard
page for the same view backed by `/api/learnings`.

## Optional: bring your own LLM

Drafting, classifying, auditing, and improving assets can be handed off to
an LLM you connect yourself — Anthropic, OpenAI, Mistral, or a local Ollama
model. See [AI Providers](/ai-providers). Nothing else in Chain Hub needs
this — it's entirely optional.
